# GearFlow 开发路线图

## 总原则

1. 每个 Phase 都要有可验证产物。
2. 不跨越 Phase 实现未来功能。
3. 每个 Phase 可以拆成多个 Git commit。
4. 文档、代码、测试同步更新。
5. 发现需求变化时，先改 PRD 和 API 文档，再实现。

## Phase 0：项目立项

**状态：已完成**

- 目标：形成完整产品和技术蓝图
- 功能：产品分析、MVP 定义、页面架构、数据模型、API、上线合规
- 涉及文件：`AGENTS.md`、`docs/`
- 前置条件：确认项目定位
- 完成标准：文档齐全且无范围冲突
- 测试要求：人工检查文档一致性
- 独立 commit：`docs(planning): complete project blueprint`

- 完成标准：详情信息完整且加载状态稳定
- 测试要求：详情数据读取测试、越权测试、异常状态
- 独立 commit：可以

## Phase 6：生命周期

**状态：代码完成（2026-08-31，ZCode 兜底验收：数据库触发器矩阵+RLS 隔离+UI 截图全通过，2c1569e 已推）；已关闭（用户验收通过：实时触发「更新设备/变更：备注」+ 回填「添加设备」均正确）。实现为 PostgreSQL 触发器（devices 写入自动追加事件），非云函数方案**

- 目标：让设备历史可追踪
- 功能：购买、保修、维护、更新、处置时间线
- 涉及文件：`DeviceTimeline` 集合、设备云函数和前端时间线组件
- 前置条件：Phase 5
- 完成标准：设备变更自动生成时间线
- 测试要求：事件顺序、软删除后不可见、用户隔离
- 独立 commit：可以

- 目标：补齐设备生命周期核心动作
- 功能：维护记录 CRUD、费用统计、保修状态计算、首页临期展示
- 涉及文件：维护页面、保修工具、`DeviceCost` 集合、维护云函数
- 前置条件：Phase 6
- 完成标准：维护记录影响时间线和统计
- 测试要求：日期边界、金额计算、状态计算
- 独立 commit：可以

## Phase 8：数据统计

- 目标：呈现资产和支出洞察
- 功能：设备数量、资产、年度支出、维护支出、分类分布、生命周期分布
- 涉及文件：统计页面、统计云函数、自绘图表组件
- 前置条件：Phase 7
- 完成标准：统计口径正确并支持空状态
- 测试要求：金额分转元、汇总、时间范围、空数据
- 独立 commit：可以

## Phase 9：测试与质量

- 目标：达到可上线质量
- 功能：单元测试、云函数测试、数据权限测试、E2E 关键路径、弱网测试、真机测试
- 涉及文件：`tests/`、CI 配置
- 前置条件：Phase 8
- 完成标准：测试通过，无阻断缺陷
- 测试要求：覆盖登录、添加设备、维护、统计、注销
- 独立 commit：可以

## Phase 10：微信小程序发布

- 目标：完成审核与上线
- 功能：小程序信息、类目、备案、隐私协议、用户协议、体验版、审核版本、CloudBase 生产环境检查
- 涉及文件：`docs/LAUNCH.md`、小程序后台配置、CloudBase 生产配置
- 前置条件：Phase 9
- 完成标准：审核通过并发布
- 测试要求：真机回归、隐私链路、注销链路、CloudBase 生产资源、成本告警
- 独立 commit：可以

## Phase 11：上线后迭代

- 目标：提升留存和使用价值
- 功能：附件、订阅消息、设备处置、年度报告、导出
- 涉及文件：CloudBase 云存储附件模块、提醒模块、报告页面
- 前置条件：MVP 已上线并收集反馈
- 完成标准：每项功能有独立指标
- 测试要求：云存储权限、提醒授权、导出数据正确
- 独立 commit：可以

## Phase 12：AI

- 目标：在数据充分后增加智能能力
- 功能：
  - AI 设备识别：上传照片，识别品牌和型号，用户确认后保存
  - AI 设备顾问：基于年限、配置、维护和成本生成建议
  - AI 年度总结：生成个人数码年度报告
- 涉及文件：AI 服务模块、附件模块、隐私评估文档
- 前置条件：Phase 11、附件能力、隐私政策更新、用户明确授权
- 完成标准：AI 结果可解释、可纠错、可关闭
- 测试要求：隐私、安全、错误处理、幻觉控制
- 独立 commit：可以
