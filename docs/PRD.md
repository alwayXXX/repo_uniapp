# GearFlow 产品需求文档（PRD）

## 1. 产品定位

### 当前交付范围（2026-10-27 用户裁定）

当前交付目标为本人使用的微信小程序体验版，Phase 10 以可构建、可上传和自用体验闭环为完成标准。正式提审、公开上架、备案与服务类目等上架专项核验，以及生产级备份恢复演练、双端真机矩阵和主动告警，移入未来公开发布清单，不阻塞本次自用交付。

自用版本继续保留协议确认、可信 OPENID 数据隔离、账号注销与本机文件清理、错误恢复和敏感数据保护。平台要求仍按实际上传结果处理；本次范围调整不代表平台审核或合规已完成。Phase 11 的每项新功能仍须单独授权。

GearFlow 是一款帮助个人用户管理设备生命周期的微信小程序。它记录设备的购买、保修、维护、升级和处置信息，并在合适的时间提醒用户处理重要事项。

GearFlow 的核心不是“设备 CRUD”，而是：

> 用一个低负担的资产台账，帮用户知道自己有哪些设备、花了多少钱、何时保修到期、何时需要维护、是否值得升级或处置。

最终形态包含三个层次：

1. **记录层**：设备档案、购买信息、保修信息、维护记录
2. **洞察层**：资产统计、年度支出、生命周期、维护成本
3. **行动层**：保修到期提醒、维护提醒、升级与处置建议

## 2. 是否值得做

### 结论

项目值得作为个人作品集核心项目推进，但必须控制预期：

- **商业上限有限**：低频工具，付费意愿不强，不适合一开始追求商业化。
- **作品集价值高**：覆盖真实账号体系、数据隔离、生命周期建模、表单、统计、提醒、微信合规和移动端体验。
- **产品成立条件**：必须把“录入成本”和“再次打开价值”作为最高优先级，否则容易变成一次性 Demo。

### 目标用户

| 用户群体           | 需求强度 | 典型诉求                                 | 优先级 |
| ------------------ | -------: | ---------------------------------------- | -----: |
| 数码爱好者         |       高 | 多设备台账、保修、升级、转售信息         |     P0 |
| 程序员 / IT 从业者 |       高 | 电脑、显示器、NAS、硬盘、配件和维修记录  |     P0 |
| 摄影用户           |       高 | 相机、镜头、存储卡、保修、维修、购买成本 |     P0 |
| 拥有大量设备用户   |       高 | 家庭设备资产统计和到期事项               |     P0 |
| 游戏玩家           |       中 | 主机、掌机、外设、购买和保修记录         |     P1 |
| 普通数码用户       |     中低 | 重要设备保修和购买凭证                   |     P1 |

首发重点不是“所有拥有设备的人”，而是 **拥有 5 台以上设备、且愿意维护资产台账的人**。

### 核心痛点

1. **信息分散**：设备信息在发票、电商订单、相册、聊天记录、备忘录和记忆中分散。
2. **Excel/Notion 维护成本高**：字段不统一、日期不自动计算、无提醒、移动端录入不流畅。
3. **关键时刻找不到**：保修到期、报修、二手出售、领取延保时才发现缺少购买日期和凭证。
4. **缺乏生命周期视角**：用户知道单个设备，但不知道总资产、年度支出、维修成本和更换周期。
5. **维护决策缺少依据**：不清楚维修是否值得、设备是否接近更换周期、哪些设备闲置。

### 再次打开场景

- 保修临近到期，需要确认购买时间和凭证
- 设备故障，需要查看序列号、维修记录和过保状态
- 购买新设备前，评估已有设备和年度支出
- 换机、出售或回收旧设备
- 每季度或每年查看设备资产报告
- 维护配件、备份硬盘、更换电池、清灰等节点

### 产品风险与对策

| 风险                | 影响               | 解决方案                                                                        |
| ------------------- | ------------------ | ------------------------------------------------------------------------------- |
| 使用频率低          | 留存不足           | 首页做“保修到期/维护待办”看板，而非只有静态列表                                 |
| 录入成本高          | 用户放弃           | 首个设备最小字段 5 项内完成；分类和常用字段可扩展                               |
| 功能复杂            | 上线慢、体验差     | P0 只保留设备、保修、维护、统计                                                 |
| Excel/Notion 可替代 | 价值感弱           | 突出日期计算、提醒、移动端录入和统计                                            |
| 微信审核与备案      | 影响未来公开发布   | 当前仅自用体验版；未来公开发布前按官方文档逐项核验                              |
| 隐私风险            | 用户抵触和法律风险 | 最小化收集、敏感字段可选、附件后置、账号注销可删数据                            |
| 服务成本            | 个人项目负担       | MVP 不做 AI 和云附件；优先使用 CloudBase 免费额度或低成本套餐，控制托管资源成本 |

## 3. MVP 范围

### P0：没有就不能成立

1. 微信登录
2. 首次使用引导
3. 设备分类
4. 设备创建、编辑、查看、删除
5. 基础购买信息：购买日期、渠道、价格
6. 保修信息：保修开始、结束、状态自动计算
7. 首页保修临期看板
8. 设备基础状态：默认“使用中”
9. 维护记录：标题、日期、类型、费用、备注
10. 设备时间线
11. 设备列表、搜索、筛选、排序
12. 基础统计：设备数量、总资产、年度支出、维护支出
13. 账号注销与数据删除
14. 隐私政策、用户协议
15. Loading、Empty、Error、网络异常、表单校验

### P1：上线后尽快增加

2026-10-27 用户明确授权 Phase 11 全清单进入本次自用迭代；范围、统计口径、隐私评估及验收标准见 `docs/PHASE11.md`。

1. 设备照片与发票附件
2. 微信订阅消息提醒
3. 扩展设备状态：闲置、已出售、已报废
4. 处置记录：出售价格、回收价格、受让方备注
5. 年度设备报告
6. 导出 JSON / CSV

实施记录：CSV 导出已于 2026-09-06 独立实现（设备清单及维护记录）。2026-09-23 收尾仅修复其完整性与本机临时文件清理，不扩展 JSON、附件、订阅消息或报告。

### P2：未来迭代

1. 设备健康度评分
2. 升级建议
3. 多端同步体验优化
4. 数据备份与恢复
5. AI 设备识别
6. AI 设备顾问
7. AI 年度总结

### 暂不考虑

- 社交和用户社区
- 二手交易
- 电商和支付
- 金融服务
- 医疗服务
- 复杂会员体系
- 复杂 AI 聊天
- 多人协作和家庭共享
- 与设备生命周期无关的功能

## 4. 核心用户流程

### 4.1 新用户

```text
打开小程序
→ 查看产品介绍
→ 微信登录
→ 授权协议与隐私政策
→ 进入首页
→ 点击添加第一台设备
→ 选择分类
→ 填写最小信息
→ 保存
```

异常情况：

- 未同意隐私政策：不能进入需要登录的功能，可浏览静态介绍
- 微信登录失败：展示重试按钮和错误说明
- 授权成功但后端异常：进入错误页，不清空已填写内容
- 用户跳过添加设备：首页展示引导卡片

### 4.2 添加设备

```text
选择分类
→ 填写名称、品牌、型号
→ 选择购买日期、渠道、价格
→ 填写保修开始和结束日期
→ 保存
→ 返回详情页
```

异常情况：

- 名称为空或超过长度限制
- 保修结束早于开始
- 购买日期晚于今天
- 价格格式错误或超出范围
- 网络中断
- 重复提交
- 编辑加载未完成或保修读取失败时禁止保存；读取失败不能被解释为用户清空保修
- 分类不存在或已被禁用

### 4.3 查看设备

```text
首页
→ 设备列表
→ 搜索 / 筛选 / 排序
→ 设备详情
→ 生命周期时间线
→ 维护记录
```

异常情况：

- 无设备：展示引导和示例说明
- 搜索无结果：展示清空条件入口
- 设备被删除后进入旧详情页：返回列表并提示数据不存在
- 数据加载失败：展示重试

### 4.4 维护设备

```text
设备详情
→ 添加维护记录
→ 填写标题、日期、类型、费用、备注
→ 保存
→ 更新维护列表与时间线
```

异常情况：

- 日期晚于今天或早于设备购买日期
- 费用格式错误
- 维护类型无效
- 保存失败但用户离开页面：提示未保存
- 维护记录超过 50 条：可继续查看旧记录，费用合计及 CSV 导出不截断

### 4.5 保修

```text
设备详情
→ 查看保修信息
→ 查看剩余天数和状态
→ P1 接收到期提醒
```

异常情况：

- 未填写保修：显示“未填写”而非报错
- 保修日期不完整：保存时提示补全或清空
- 提醒未授权：只提供站内提示，不阻断主流程

### 4.6 数据统计

```text
首页或数据页
→ 选择统计范围
→ 查看资产、支出、维护、生命周期
→ 下钻查看设备列表
```

异常情况：

- 无数据：展示空状态
- 金额汇总异常：后端必须使用整数分计算
- 时间范围无效：回退默认今年

### 4.7 删除设备

```text
设备详情
→ 点击删除
→ 二次确认
→ 删除设备及关联记录
→ 返回列表
```

异常情况：

- 误删：删除前明确提示影响范围；P1 可增加回收站
- 网络失败：保持数据不变
- 删除后详情页残留缓存：成功后清理本地缓存

## 5. 页面信息架构

### 结论

采用四个 Tab：

```text
首页 / 设备 / 数据 / 我的
```

理由：

- 首页承接待办和再次打开价值
- 设备页承接主资产管理
- 数据页承接洞察价值
- 我的页承接账号、协议、隐私和注销

### 页面清单

| 页面          | 职责                   | 核心功能                                 | 入口              | 出口                     |
| ------------- | ---------------------- | ---------------------------------------- | ----------------- | ------------------------ |
| 首页          | 展示重要状态和快捷入口 | 保修临期、最近维护、设备总数、添加设备   | Tab 启动          | 设备详情、添加设备、统计 |
| 设备列表      | 管理全部设备           | 搜索、筛选、排序、分类、创建             | Tab、首页快捷入口 | 设备详情、添加设备       |
| 添加/编辑设备 | 维护设备档案           | 分类、基础、购买、保修表单               | 列表、详情        | 详情或列表               |
| 设备详情      | 单设备完整视图         | 基础信息、保修、维护、时间线、编辑、删除 | 列表、首页        | 编辑页、维护表单、列表   |
| 维护记录表单  | 新增/编辑维护          | 标题、日期、类型、费用、备注             | 设备详情          | 设备详情                 |
| 数据统计      | 展示资产与成本洞察     | 数量、资产、支出、维护、生命周期分布     | Tab               | 下钻设备列表             |
| 我的          | 账号与合规             | 用户信息、协议、隐私、注销               | Tab               | 协议页、注销流程         |
| 登录引导      | 建立账号关系           | 登录、协议确认                           | 未登录触发        | 首页                     |
| 首次引导      | 解释价值               | 三步介绍、添加第一台设备                 | 首次启动          | 添加设备、首页           |

### 页面关系

```text
首次启动
  └─ 首次引导 ── 登录 ── 首页

首页 ── 添加设备 ── 设备列表
  ├─ 设备详情 ── 编辑设备
  ├─ 设备详情 ── 维护记录表单
  ├─ 设备详情 ── 时间线
  └─ 数据统计 ── 下钻设备列表

我的 ── 隐私政策 / 用户协议
  └─ 账号注销
```
