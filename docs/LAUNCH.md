# GearFlow 微信小程序上线与合规清单

> **重要声明**：微信平台政策、备案要求、隐私规则和审核标准会变化。以下信息基于 2026-08-29 可访问的微信官方文档整理，**必须在实际开发、提审和发布前再次核实最新官方规则**。

## 2. 小程序基础配置

### 2.1 注册与主体

- 确认小程序主体类型：个人主体或非个人主体
- 确认管理员、开发者、体验者权限
- 确认小程序名称、头像、简介与 GearFlow 功能一致
- 确认服务类目符合实际功能

### 2.2 类目判断

GearFlow 属于个人设备信息管理工具，不涉及：

- 社交
- 交易
- 支付
- 电商
- 金融
- 医疗

提审前必须在官方“开放的服务类目”文档中确认个人主体可选类目，并按实际功能选择。

### 2.3 CloudBase 与小程序绑定

当前阶段不规划自有 API 域名、独立服务器、Nginx 或自维护 HTTPS 证书。发布前需要确认：

- CloudBase 环境与当前微信小程序 AppID 正确绑定
- 前端只保存 CloudBase 环境 ID 等公开配置
- 微信 AppSecret、CloudBase 管理凭据和服务端密钥不出现在客户端代码
- 如平台要求配置合法域名，按 CloudBase 和微信官方文档当时给出的域名清单执行
- 开发数据与生产数据隔离

不自行购买 VPS，不自行部署 MySQL / PostgreSQL，不自行维护 Nginx。

## 3. 备案

根据官方《小程序备案操作指引》：

- 在中国大陆提供非经营性互联网信息服务需依法履行备案手续
- 小程序后台提供备案入口
- 备案前需准备主体、负责人、小程序信息及相关材料
- 涉及特定前置审批类业务时需提交对应审批文件

GearFlow 目标：

- 非经营性个人工具
- 不做交易、支付、社区和信息服务发布
- 不设计需要前置审批的功能

上线前必须确认：

- 当前是否必须完成备案后才能上架
- 个人主体备案材料
- 小程序服务内容描述
- 工信部短信核验流程
- 备案状态

## 4. 隐私与用户协议

### 4.1 必须提供

- 《用户协议》
- 《用户隐私保护指引》或隐私政策
- 账号注销入口
- 用户数据删除能力

### 4.2 最小化收集

GearFlow 收集：

| 数据                   | 是否必需         | 用途                     |
| ---------------------- | ---------------- | ------------------------ |
| CloudBase 用户身份标识 | 必需             | 账号识别与数据隔离       |
| 微信 OpenID            | 如业务需要才保存 | 由服务端处理，不返回前端 |
| 设备名称、分类         | 必需             | 资产管理                 |
| 购买日期、价格         | 可选             | 成本统计                 |
| 保修日期               | 可选             | 状态计算和提醒           |
| 维护记录               | 可选             | 生命周期管理             |
| 序列号                 | 可选             | 报修辅助，默认提示非必需 |
| 昵称、头像             | 可选             | 展示，可以不提供         |
| 设备照片、发票         | P1 再收集        | 凭证管理，MVP 不做       |

### 4.3 隐私声明必须覆盖

如果 MVP 使用微信登录 / CloudBase 身份认证，必须声明：

1. 收集用户登录标识
2. 收集目的
3. 使用范围
4. 保存期限
5. 用户查询、更正、删除数据的方式
6. 账号注销方式
7. 开发者联系方式

如果后续启用图片上传、订阅消息或 AI，必须重新更新隐私声明，并保证声明与实际接口调用一致。

### 4.4 敏感数据规则

- 序列号、发票、照片默认不强制填写
- 日志禁止输出敏感数据
- 附件访问必须通过 CloudBase 云存储权限或临时访问能力授权
- 附件访问必须校验用户归属
- AI 服务启用前必须单独评估第三方数据流转

## 5. 账号注销与数据删除

小程序内必须提供可见入口，不能只放在文档中。

流程：

```text
我的
→ 账号注销
→ 展示影响范围
→ 二次确认
→ 删除用户数据
→ 退出登录
```

必须删除：

- 用户资料
- 设备
- 保修
- 维护记录
- 时间线
- 统计成本
- 附件及 CloudBase 云存储文件
- 同意记录中的可识别信息
- GearFlow 客户端登录态和本地缓存

## 6. 用户身份

当前阶段优先使用 CloudBase 面向微信小程序提供的用户身份认证与数据权限能力，不自行实现 `code2Session + JWT` 会话体系。

核心流程：

```text
小程序建立 CloudBase 身份
→ 云函数读取可信用户上下文
→ 创建或查询 GearFlow User
→ 安全规则限制用户只能访问自己的数据
```

安全要求：

- AppSecret 和 CloudBase 管理凭据只能保存在服务端或平台配置中
- 不把 AppSecret 打包进小程序
- 不向客户端返回 OpenID 或管理凭据
- `userId` 必须由可信身份上下文派生，客户端不能传入
- 账号注销后 GearFlow 业务数据不可访问，云存储文件同步删除
- 平台身份生命周期按 CloudBase 与微信官方规则处理

## 7. 订阅消息

MVP 不实现订阅消息。P1 用于保修到期提醒。

启用前必须：

1. 在小程序后台申请或选择合适模板
2. 用户主动触发授权
3. 不诱导、不强制授权
4. 明确提醒内容和频率
5. 更新隐私政策
6. 核实最新官方订阅消息规则

## 8. 图片与附件

MVP 不实现图片上传。

P1 启用前必须：

- 限制文件类型和大小
- 使用 CloudBase 云存储，数据库只保存文件引用和元数据
- 服务端生成随机云存储路径
- 不信任原始文件名
- 校验 MIME 和文件内容
- 访问必须经过 CloudBase 云存储权限或临时访问授权
- 删除设备和账号时删除文件
- 在隐私政策中说明用途和保存期限

## 9. 审核风险与规避

| 风险                 | 规避方式                                      |
| -------------------- | --------------------------------------------- |
| 功能空白或 Demo 化   | 提审前完整实现核心流程                        |
| 类目不符             | 只保留设备管理工具功能                        |
| 隐私声明与接口不一致 | 提审前核对接口调用                            |
| 登录强制             | 静态介绍页可浏览                              |
| 账号注销不可用       | 提审前真机验证                                |
| CloudBase 环境不可用 | 检查小程序 AppID 绑定、环境状态和平台域名要求 |
| 诱导授权             | 订阅消息延后且用户主动触发                    |
| 数据删除争议         | 后端真实删除，不做假删除                      |
| 内容审核风险         | 不提供社区、发布、分享 UGC                    |
