# Phase 11 自用功能迭代

**状态：已完成（2026-10-28，自用体验版范围）**。五项功能已实现并完成下述核心验收，1.2.0 已设为体验版；本人 iPhone 已确认收到保修提醒，附件上传、查看、删除均正常。公开上架不在本次范围，Phase 12 未开启。

## 范围与验收

2026-10-27 用户明确授权「P11 按清单逐项做完」。本次依次实现设备处置、年度设备报告、JSON 导出、照片/发票附件和保修到期订阅提醒；保留已有 CSV，不进入 AI。

- 处置：出售/报废日期、收入和备注，更新状态并追加不含原值的时间线；收入独立展示，不改变原购买/维护统计。
- 年报：按自然年汇总购买、维护、处置收入与月度变化；仅统计当前保留且未软删除设备，不宣称重建已删除数据或历史年末快照。人民币整数分，支持合法历史年度与无数据。
- JSON：导出本人未删除设备及关联维护、保修、处置信息，剔除身份和云文件地址。复用本机文件分享/清理，不包含附件二进制，不实现导入恢复。
- 附件：每设备最多 10 个，每文件最多 2 MiB，JPEG/PNG/WebP/PDF；后端校验文件头、大小和设备归属，随机云路径，客户端不能任意指定 fileID。预览经鉴权云函数读取文件内容，以兼容微信域名校验；本机专用预览目录在应用再次显示、页面刷新和退出时清理。删除附件、设备和账号均先清理云文件，再清理元数据，失败可重试。
- 提醒：用户主动选择设备和日期，点击一次性订阅授权，拒绝不创建任务。平台模板未就绪时展示未配置态。定时任务条件更新领取，避免重复发送；取消、删除设备和注销均撤销未发送任务。发送结果不明不自动重发。

## 架构、API 与数据

沿用 `gearflow-api` Event Function、Nodejs18.15、可信 OPENID 与 CloudBase MySQL。新增 `device_attachments`、`device_reminders`；设备现有处置日期/金额字段复用，处置说明写入独立 `disposal_notes` 列。新增 API：`device.dispose`、`report.annual`、`export.json`、`attachment.list/upload/open/delete`、`reminder.config/list/create/cancel`。API 类型集中于 `src/types/api/phase11.ts`，所有业务参数由服务端再次校验。识别标题含保修/到期或标题为“待办事项提醒”、类型为一次性且字段可映射的已有订阅模板，不自动添加模板。

用户已添加“待办事项提醒”（记账类目，场景为台账）并提供截图：提醒内容 thing2、到期日期 time3、提醒时间 time16。本轮适配将提醒内容写为设备简称加“保修即将到期”（最多 20 个字符）；日期型到期字段仍用保修结束日，time 型用该日北京时间 23:59，与按日保修口径一致；提醒时间用实际发送时的北京时间。只接受提醒时间/日期语义的额外 time/date 字段，不填充含义未知的时间字段。extra_fields 复用 JSON 列，新任务存 fields/content 对象以区分提醒内容模式，发送时兼容旧字符串数组；无需数据库迁移，客户端接口和协议版本不变。

手机授权后用户反馈通用“请求失败”，但只读核对已有 2026-10-28 的 PENDING 计划，当前提醒页也可显示。不能将此记录为授权失败；已发现同日重复请求原先返回校验错误，本轮改为同设备、日期、模板及保修结束日相同且仍为 PENDING 时返回原计划，不重复写入或取消它。SENDING/SENT/UNKNOWN 仍拒绝重复安排；真实手机重试结果继续单独核对。

所有用户查询按可信 OPENID 过滤，报表和导出完整分页读取。附件由云函数上传，本功能不使用客户端云存储直读写；云存储规则须保持私有（仅创建者和管理员可访问），元数据不得公开。定时入口校验运行环境注入的来源，不能相信客户端 event 自报定时来源。

2026-10-28 整点检查发现真实计划仍为 PENDING；SCF ListTriggers 已确认触发器 Enable=1、Available、绑定 $LATEST。原入口只接受 wx_trigger 来源，可能不兼容独立 SCF 定时调用；旧日志接口已下线且本环境未开启 CLS，不能据此臆断实际来源值。增加服务端专用 GEARFLOW_TIMER_TOKEN，通过 SCF 托管环境变量和触发器 CustomArgument 配置，值不打印、不写仓库或本机配置、不进入客户端；使用恒定时间比较，仍要求无可信 OPENID、正确 Timer 类型与触发器名称。配置脚本合并保留现有环境变量，重复运行复用既有凭据。验证模式临时每分钟扫描，在 finally 中恢复原周期；不新增消息、用户或数据库迁移，处理本人已经授权的到期计划。

补充验证已完成：定时器专用凭据配置后真实计划被领取，发送接口结果不明时保守记为 UNKNOWN，未自动重发。本人随后明确确认「已收到保修提醒」，因此该条计划可按人工收件确认对账为 SENT，并在 extra_fields 记录 USER_CONFIRMED，不能冒充 SDK 返回成功。验证脚本已确认原 cron `0 0 * * * * *` 恢复。每次重新部署云函数后运行 `node scripts/configure-reminder-timer.mjs --cli <已安装的CLI入口>` 维护专用凭据及触发器参数；`--verify` 仅用于已授权、已到期计划的短窗口验证。

## 隐私与安全先行评估

附件可能包含姓名、地址、序列号、金额；选择前说明只用于本人凭证管理，建议遮盖无关信息。不识别、不训练、不公开分享。存储于国内 CloudBase 至主动删除附件/设备或注销；云文件地址和内容不写日志、不导出。本机预览临时文件及时清理。

订阅只记录设备、计划日期、模板和任务状态，不采集手机号、不强制授权、不群发；可取消未发送任务，保修/状态变化取消旧计划。消息只含设备名称、保修日期和固定提示，不含序列号、价格和附件地址。以微信真实模板、用户授权及平台权限为准，不引入 AppSecret。

隐私政策升级至 1.1.0，显式重新同意后启用新增能力。日志仅输出固定错误码，不序列化 SDK 异常。平台隐私声明需与实际文件选择/订阅调用一致；未配置模板、存储权限或定时器时，不宣称平台链路已完成。
