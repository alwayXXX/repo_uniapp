# P12 数据库变更草案

目标环境：`myrepo-d7go4fyg918beac63`，现有 CloudBase MySQL。此文件是待审查的计划，**尚未执行**；实际 SQL 见 [phase12-draft.sql](../database/mysql/phase12-draft.sql)。

1. 在现有 `users` 表的 `(openid, status)` 上新增唯一索引，供两个新表的复合外键引用；不修改现有行。建索引可能短暂影响数据库操作。
2. 新建 `ai_daily_quota`，记录每个账号的每日调用次数，用于服务器端限流。
3. 新建 `ai_grants`，记录短时授权的摘要和使用状态，防止重复调用。它不保存图片、设备摘要、模型回复或明文签名凭证。

两个表都关联现有账号：账号进入删除状态时授权记录随状态冻结；注销过程清除该账号的 AI 记录。旧的设备、维护、保修、附件、提醒和协议记录不改动。删除旧表、清空数据和迁移环境不在计划内。

执行前确认本人可用的备份、实时表结构、索引和表名；逐条执行，任一步失败即停止，先检查实际状态，不能直接重复非幂等的 `ALTER TABLE`。建表后核对外键和访问权限，再用隔离测试验证云端 SDK 的条件更新及账号隔离；不拿真实账号做注销测试。未配置密钥和部署 AI 函数前，新表不会启用 AI。线上业务函数依赖两表，不能在迁移前部署新版业务函数。

本地 MySQL 8 隔离环境已使用虚构数据验证建表、外键级联及冻结行为，但尚未验证 CloudBase MySQL 的生产权限和 SDK；开发者工具的身份探针已验证，iPhone 和微信原生定时器仍须验证。若发布出现问题，应先停止 AI 入口并保留表与业务数据排查；任何删除表或回滚数据的操作需要另行评估。
